# Подключение Supabase (полная версия)

Приложение полностью переведено на Supabase:

- **Аккаунты** — реальная регистрация/вход по e-mail + паролю.
- **Поиск людей и личные чаты (DM)** — находите зарегистрированных пользователей
  по имени или @username и переписываетесь в реальном времени.
- **Личные данные** (профиль, контакты, настройки, стикеры, звонки) — синхронизируются через таблицу `user_data` (по одному JSON-снимку на стор).
- **Чаты, каналы, группы, сообщения** — реальные общие сущности в реляционных таблицах с **realtime**: создаёте канал/группу → они появляются у других участников; сообщения прилетают мгновенно.
- **Публичные профили** (`profiles`) — имя/аватар видны другим (поиск, участники групп, DM).
- **Статусы «онлайн / был недавно»** — через Supabase Realtime Presence: в личных
  чатах виден зелёный индикатор у тех, кто сейчас в сети, иначе — время последнего визита.
- **Аватары в Supabase Storage** — фото профиля, каналов и групп загружаются в
  публичный bucket `avatars` (вместо тяжёлых data-URL в базе).
- **Счётчики непрочитанных** — бейджи на чатах и на вкладке «Чаты»; отметка
  прочтения (`chat_members.last_read`) ставится при открытии чата.
- **Уведомления** — реальные браузерные уведомления (Notifications API) + звук и
  вибрация при новом сообщении в любой чат (личка/группа/канал/бот), если этот
  чат не открыт или вкладка свёрнута. Включаются в Настройки → Уведомления.
- **Фоновые Web Push** — уведомления приходят даже при закрытой вкладке (service
  worker + VAPID + Edge Function). Настройка — см. `supabase/PUSH_SETUP.md`.
- **Статус бота** — тест-бот всегда показывает «бот · в сети».

## Архитектура данных

| Таблица        | Назначение                                                        |
|----------------|-------------------------------------------------------------------|
| `user_data`    | JSON-снимки личных сторов (настройки, контакты, стикеры, звонки).  |
| `profiles`     | Публичный профиль (имя, username, аватар, цвет).                  |
| `chats`        | Чаты: бот, личные, каналы, группы + метаданные и списки для UI.   |
| `chat_members` | Кто в каком чате и с какой ролью (owner / admin / member / pending). |
| `messages`     | Сообщения и посты (с реакциями, ответами, закреплением).          |

Плюс публичный **Storage bucket** `avatars` — для фото профиля/каналов/групп.

Все таблицы защищены **Row Level Security**: пользователь видит только свои
чаты, чаты где состоит, и публичные каналы/группы (для перехода по ссылке).

### Как это работает в коде

- `src/lib/chat-remote.ts` — преобразование строк БД ↔ доменные типы и CRUD.
- `src/lib/chat-store.tsx` — состояние в памяти остаётся источником для рендера
  (мгновенные оптимистичные обновления), но теперь:
  - при входе грузит чаты из БД (`loadMyChats`);
  - подписывается на realtime по таблице `messages`;
  - зеркалит каждое изменение (отправка/редактирование/реакция/удаление,
    создание канала/группы, вступление, управление участниками) в Supabase.
- Чат с ботом создаётся персонально для каждого пользователя (`bot_<uid>`).

## ⚠️ Обязательный шаг — применить схему (один раз)

Создание таблиц нельзя сделать через API-ключи, только через дашборд:

1. https://supabase.com/dashboard → проект `sgzvjgxbdpiflpypqisd`.
2. **SQL Editor → New query**.
3. Вставьте всё содержимое `supabase/schema.sql` → **Run**.

Скрипт идемпотентен (можно запускать повторно): создаёт таблицы, политики RLS,
вспомогательные функции и включает realtime.

### Порядок выполнения SQL-скриптов

Запустите по очереди (каждый идемпотентен, можно повторять):

1. `supabase/schema.sql` — базовые таблицы, RLS, realtime.
2. `supabase/admin.sql` — админ-панель, бан-система, статистика.
3. `supabase/badge.sql` — бейдж «Багхантер».
4. `supabase/premium.sql` — **HouseGram Premium** и «Закрытая личка».
5. `supabase/promo.sql` — **промокоды Premium** (выдача Premium по коду).

После `premium.sql` появятся:
- колонки `profiles.premium_until`, `profiles.dm_closed` и `profiles.premium_status`;
- RPC `admin_grant_premium(_username, _days)` и `admin_revoke_premium(_username)`
  (только для админа `goh@gmail.com`) — используются в админ-панели для выдачи
  Premium по username на N дней;
- правило: пока у пользователя активен Premium и включена «Закрытая личка»,
  ему нельзя написать в личные сообщения (проверка в политике `messages_insert`).
  Исключения — отправитель с активным Premium, а также тот, кто **уже писал**
  в этот чат ранее (существующие диалоги остаются открытыми, как в Telegram).

После `promo.sql` появятся:
- таблицы `promo_codes` (код, дни Premium, лимит и счётчик активаций) и
  `promo_redemptions` (кто какой код активировал — защита от повтора);
- RPC `admin_create_promo_code(_code, _premium_days, _max_activations)`,
  `admin_list_promo_codes()`, `admin_delete_promo_code(_code)` — только для
  админа `goh@gmail.com`, используются в админ-панели для создания и управления
  промокодами;
- RPC `redeem_promo_code(_code)` — любой пользователь активирует код в
  «Настройки → HouseGram Premium → У меня есть промокод» и получает Premium
  на указанное число дней (продление от текущей даты окончания).

## Проверка многопользовательского режима

1. `npm run dev`, откройте http://localhost:3000
2. Зарегистрируйте **двух** пользователей (например, в обычном окне и в инкогнито).
   У каждого зайдите в Настройки → профиль и задайте имя/@username — по ним ищут.
3. Личный чат: у пользователя A нажмите «+» → «Новое сообщение», найдите B по
   имени или @username, откройте чат и напишите сообщение.
4. У пользователя B чат и сообщение появятся автоматически (realtime).
5. Канал/группа: A создаёт, копирует ссылку-приглашение (кнопка «Пригласить» / QR),
   B открывает ссылку и присоединяется → видит историю; новые сообщения у обоих
   появляются в реальном времени.
6. Добавить реальных людей в группу: откройте инфо группы → «Найти людей в Supabase»,
   найдите по имени/@username и добавьте. Группа сразу появится у добавленного
   пользователя (realtime), он видит историю и пишет в неё.

## 🔐 Безопасность

Секретные ключи были переданы в чате открытым текстом — **смените их** в дашборде:
**Project Settings → API → Rotate** (для secret/`service_role`).
Публичный (`anon`/publishable) ключ можно оставить — он безопасен для клиента,
доступ ограничен политиками RLS.

## Ограничения

- Управление участниками устроено двухслойно: локальные контакты (демо) для
  оформления, и реальные пользователи Supabase (таблица `chat_members`) —
  именно они определяют доступ к чату по политикам RLS. Добавляйте реальных
  людей через «Найти людей в Supabase».
- Уведомления работают, пока приложение открыто или свёрнуто (вкладка в фоне).
  Полностью «фоновые» пуши при закрытом браузере требуют Web Push (VAPID +
  service worker + сервер для отправки) — это отдельный слой, которого нет в
  чисто клиентском приложении.
- Аудио/видеозвонки используют PeerJS (P2P) и не зависят от Supabase.
